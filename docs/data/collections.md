# Book, Topic, Collection

**Spec version:** 1

> Conventions (uid, script codes, types) are in [`README.md`](README.md).

## Purpose

Three grouping entities let readers browse songs by more than author. They share a common shape (a
titled set of song references) but differ in meaning:

- **Book** — a published songbook; songs have a defined order within it.
- **Topic** — a thematic tag (deity, festival, mood); order is not significant.
- **Collection** — a curated/user-facing set (e.g. "Morning kirtans", festival-day bundles).
  **Deferred**: a curated set is only meaningful once a reader can own one, which needs auth +
  accounts. No `collection`-kind groups ship, `getSongGroups('collection')` returns `[]` (asserted
  by test), and the sidebar's Collections group is commented out — see
  [`../screens/navigation.md`](../screens/navigation.md).

## Common shape — `SongGroup`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `uid` | string | yes | Stable identifier. |
| `kind` | enum(book, topic, collection) | yes | Which grouping this is. |
| `titles` | list<ScriptText> | yes | Group name across scripts. At least one. |
| `song_uids` | list<ref<Song>> | yes | Member songs. |
| `ordered` | boolean | yes | `true` for books (song order is meaningful), else `false`. |
| `color` | string | no | Display accent (used by Topic tags; see theme). |

## Invariants

- `uid` unique within its `kind`.
- Every entry in `song_uids` resolves to an existing [Song](song.md).
- When `ordered = true`, `song_uids` order is authoritative for display.
- A song may belong to any number of groups of any kind.
- A `Song.topics[]` reference and a Topic's `songUids[]` membership must agree (bidirectional
  consistency).

## Example

```jsonc
{ "uid": "topic-nityananda", "kind": "topic", "ordered": false,
  "titles": [{ "scriptCode": "Latn", "text": "Nityānanda" }],
  "songUids": ["N9", "A1"], "color": "#B36B00" }
```


## Taxonomy (rebuilt from the Gīti-guccha hierarchy)

`song_groups.json` is rebuilt by `pipeline/rebuild_song_groups.py` from the authoritative
`gg_hierarchy.json` (the 2024 Gīti-guccha FINAL CHECK). The old audio-folder-derived groups conflated
languages/themes/works under "book" and had 188 mostly single-song junk topics; those are removed.

- **Topic** = a theme (the Gīti-guccha thematic chapters: Śrī Guru, Śrī Kṛṣṇa, Śrī Rādhā, Vaiṣṇavas,
  Pañca-tattva, Chant the Holy Name, Ārati, …). 14 topics, each ≥4 songs.
- **Book** = a named literary WORK: whole-chapter works (Śaraṇāgati, Śrī Śikṣāṣṭaka, Śrī Upadeśāmṛta,
  Śrī Nāmāṣṭaka) + cross-cutting source books named in sub-topic headers (Kalyāṇa-kalpataru, Gītāvalī,
  Śrī Manaḥ-śikṣā). 7 books. A song may carry a topic AND a source book.

## Data source (groupings now ship)

`song_groups.json` is generated by `pipeline/build_song_groups.py`, **merging two sources**:
1. **Audio `src` paths** (authoritative, clean) — the team's own file organization baked into the
   song data, e.g. `"17 Ārati/[07] Śrī Gaura Ārati/…"` → book **Ārati**, topic **Śrī Gaura Ārati**.
   Covers the 235 songs with audio, with clean names.
2. **Śrī Gauḍīya Gīti-guccha PDF Contents** — adds non-audio songs + finer topics, matched to corpus
   uids by normalized fuzzy match (diacritic-strip + v/b, j/y fold), verified against uid prefixes
   (e.g. Śrī Guru book = `G`-prefixed songs).

Src wins for book names (clean); books are merged by normalized key; junk/front-matter/filename
topics are filtered. Result: **24 books, 188 topics, 287 grouped songs** (up from a PDF-only 184).
Songs not in these sources carry no group (fine — they still appear in the main list).

**Cover images** (optional): a few books have covers on the bucket at
`https://gaudiyakirtan.s3.amazonaws.com/collections/<slug>.jpg` (`gaura`, `nitai`, `radha`); others
use `color`. Load with graceful fallback (most slugs 404).
