The user imported `gaudiyakirtan/gaudiyakirtan` directly (project `gaudiyakirtan-dev`, root `web`).

    while staying same-major to avoid Next 16 breaking changes. Verified build + audit (critical
    gone; remaining highs are transitive sharp/postcss, not what Vercel blocks on). → commit `42e72da`.

  serving `web/public/` as a plain static directory** — only the `.md` twins resolved and `/` fell
  through to `public/index.md`. Confirmed `next start` serves correctly locally ⇒ **Vercel-specific**

  - **Alternatives.** Change the dashboard Framework Preset; or force it in code.
  - **Chosen — `web/vercel.json` with `"framework": "nextjs"`** (plus `buildCommand: pnpm run build`

  - **Why.** Deterministic and survives future redeploys — no dashboard state to remember. → `30a8bf0`.

## Stage 11 — PWA (`a061c80`)

- **Decisions.** **Hand-rolled service worker**, no `next-pwa`/Workbox, zero new deps (Next-15
  support for those is shaky). **Cross-origin bypass by construction** (origin check, not a hostname
  allowlist) so the S3 audio bucket is never intercepted → Range-request seeking is safe and the
  rule can't drift from `config.ts`. Cache-first for hashed `/_next/static`; **stale-while-revalidate**
  for everything same-origin (a missed `CACHE_VERSION` bump then degrades to one stale view, not a
  pinned build). Precache only a 3-URL shell, not 736 pages. Manifest colors from the real Gaura/Shyam
  palette; `purpose: "any"` (not maskable — the art bleeds to the canvas edge).
- **Issue I caught in review.** `/` was precached into `SHELL_CACHE` but the fetch handler only read
  `RUNTIME_CACHE`, so the precache was dead weight and a first-ever offline home visit fell through to
  `offline.html`. **Fixed** to consult the shell cache before the offline fallback.
